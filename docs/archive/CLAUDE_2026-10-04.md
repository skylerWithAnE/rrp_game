# rrp_game

Online co-op Unity prototype (3 to 4 players, up to 8, one player hosts): a crew of blobs builds a
**road** across a deformable desert, and the only tool is the shovel. Digging pops out physics cubes
the crew has to deal with; leave too many lying around and an earthquake punishes them. Scenarios
are 20 to 30 minute replayable jobs chased for high scores. The first is **the Hill**: connect two
towns with a large hill between them. Prototype-grade art (solid colors, blobby characters,
procedural animation only). It began as a railroad idea on 2026-10-04.

Read these before doing design or implementation work:

- `docs/DESIGN.md` — the game: what the user asked for, the build loop, tuning numbers, open questions.
- `docs/TECH_PLAN.md` — proposed architecture (terrain, networking, animation, milestones). Proposals, not yet confirmed by the user unless marked.
- `docs/SETUP.md` — machine/tooling state and the remaining setup steps for Unity + MCP.

## Ground rules from the user

- This is a prototype. Favor fast, dumb, and funny over correct and polished. "It's dumb. Cool."
- Solid-color shaders only. No textures, no imported art.
- Characters are solid-color blobs.
- All animation is procedural (code-driven). No animation clips, no Animator controllers.
- Resources are placed in the world for players to collect for now; "more weird gameplay" comes later.

## Working conventions (Claude's proposal)

- Code-first: build the world from scripts at runtime (procedural meshes, materials created in code,
  one small bootstrap scene) rather than hand-authored scenes and prefabs. Text diffs stay readable
  and Claude can change things without fighting Unity YAML.
- Every gameplay number lives in one tuning ScriptableObject/static config so it can be changed fast.
- In the docs, keep "user decided" separate from "Claude proposed". Don't promote a proposal to a
  decision without the user saying so.
